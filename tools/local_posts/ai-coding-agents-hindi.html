दो साल पहले तक AI coding tool का मतलब एक ही चीज़ था — line ke aage ka code भविष्यवाणी करने वाला autocomplete. अब तस्वीर बदल चुकी है। नए tools से आप कहते हैं "इस bug को ठीक करो और test भी चला दो", और वे खुद repo में files ढूँढते हैं, code बदलते हैं, command चलाते हैं, और diff दिखाते हैं। इन्हें AI coding agent कहते हैं।

इस guide में मैं तीन तरह के tools का फर्क खोलूँगा — terminal agent (जैसे Claude Code), cloud agent (जैसे OpenAI Codex) और editor में रहने वाला assistant (जैसे GitHub Copilot). साथ में यह भी बताऊँगा कि किस काम में कौन सा सही है, कौन से guardrails ज़रूरी हैं, और वे तीन स्थितियाँ जहाँ agent लेना पैसे की बर्बादी है।

छोटा जवाब: Autocomplete आपकी उँगली से पहले code लिख देता है; agent आपके repo में काम करता है, files बदलता है और tests चलाता है। छोटे बदलावों के लिए editor का assistant सबसे तेज़ है, लंबे multi-file काम के लिए terminal या cloud agent बेहतर है। किसी भी हालत में agent का output बिना diff पढ़े merge न करें — यह एक आदत पूरे जोखिम का 80% हटा देती है।

Autocomplete, chat और agent — तीन अलग चीज़ें

Autocomplete वह है जो आपके टाइप करते ही अगली line सुझाता है। इसका दायरा आपकी current file और थोड़ा सा आसपास का code होता है। यह सबसे तेज़ है, सबसे सस्ता है, और रोज़ के काम में सबसे ज़्यादा समय बचाता है — बशर्ते आप हर suggestion पढ़कर स्वीकार करें।

Chat वह है जहाँ आप code चिपकाकर पूछते हैं "इसमें क्या गलती है"। यह समझाने में अच्छा है, पर आपको ही code इधर-उधर ढोना पड़ता है। Agent तीसरा स्तर है: उसे काम बताया जाता है, और वह खुद tools चलाता है — file search, read, edit, terminal. यही वजह है कि agent को permission और limits चाहिए; वह आपकी machine पर असली command चला सकता है।

तीनों की तुलना एक उदाहरण से करें। काम: "login form में validation जोड़ो और उसका test लिखो." Autocomplete आपको validation की lines सुझा देगा। Chat पूरा function लिखकर देगा, जिसे आप चिपकाएँगे। Agent खुद form की file ढूँढेगा, देखेगा कि project में कौन सी validation library पहले से है, उसी style में code लिखेगा, test file बनाएगा, test चलाएगा, और अगर fail हुआ तो दोबारा ठीक करेगा।

तीन तरह के tools, तीन जगह

Terminal agent — Claude Code

Claude Code एक agentic coding tool है जो terminal में चलता है। आप अपने project folder में उसे खोलते हैं और सामान्य भाषा में काम बताते हैं। वह repo पढ़ता है, ज़रूरी files खोजता है, code बदलता है, command चलाता है और नतीजा दिखाता है। काम के बीच में वह permission माँगता है — खासकर जब file लिखनी हो या command चलानी हो।

इसका सबसे बड़ा फायदा है "आपके माहौल में चलना": वही Node version, वही database, वही env file जो आपके laptop पर है। इसीलिए debugging में यह मज़बूत है — error असली में वहीं पैदा होता है। दूसरा फायदा है CLAUDE.md जैसी project memory file, जिसमें आप project के नियम लिखकर रखते हैं, ताकि agent हर बार वही गलती न दोहराए।

नुकसान यह है कि यह आपकी machine पर सीधा हाथ रखता है। अगर आपने उसे broad permission दे दी, तो वह गलत file बदल सकता है या ऐसी command चला सकता है जो आप नहीं चाहते थे। इसलिए इसे हमेशा git वाले folder में चलाएँ, जहाँ आप एक command से सब वापस ला सकें।

Cloud agent — OpenAI Codex

Codex का cloud रूप आपके काम को एक अलग environment में चलाता है। आप task देते हैं, वह repo की copy में काम करता है, और नतीजा pull request या patch के रूप में लौटाता है। आपका laptop बंद भी हो तो काम चलता रहता है — यही इसका सबसे बड़ा फायदा है।

Cloud agent उन कामों के लिए अच्छा है जो साफ़ लिखे जा सकें: "इस endpoint के लिए pagination जोड़ो", "इन 12 files में deprecated API बदलो", "इस issue का fix और test लिखो". जहाँ काम में बहुत सारा local setup, secret या बाहर की service चाहिए, वहाँ cloud environment में दिक्कत आती है — क्योंकि वहाँ आपका पूरा माहौल नहीं होता।

इसका दूसरा पहलू है review की आदत। जब agent आपके लिए PR बनाता है, तो आपका काम code लिखने से बदलकर code पढ़ने में बदल जाता है। अगर टीम में review की संस्कृति कमज़ोर है, तो cloud agent बहुत सारे औसत PR पैदा कर देगा जिन्हें कोई ध्यान से नहीं पढ़ेगा — और तकनीकी कर्ज़ बढ़ेगा।

Editor assistant — GitHub Copilot

Copilot का सबसे पुराना और सबसे इस्तेमाल किया जाने वाला रूप editor के अंदर autocomplete है। इसके साथ chat भी है, जहाँ आप चुने हुए code के बारे में पूछ सकते हैं, और agent mode भी है, जो चुने हुए काम पर multi-file बदलाव कर सकता है और command चला सकता है।

इसका फायदा यह है कि यह आपके काम की जगह पर ही है — context switch नहीं करना पड़ता। आप लिख रहे हैं, suggestion सामने आ गया, Tab दबाया, आगे बढ़े। रोज़ के छोटे-छोटे कामों में इससे ज़्यादा तेज़ कुछ नहीं।

नुकसान यही है कि editor के अंदर का agent अक्सर terminal agent से कम "पूरा repo देखने" वाला होता है। बड़े refactor, पुराने code की खोज और लंबी debugging में terminal या cloud agent ज़्यादा भरोसेमंद रहता है।

Guardrails: agent को repo में घुसाने से पहले

Branch अलग रखें। Agent को कभी सीधे main पर काम न करने दें। उसकी अपनी branch हो, और आपका main हमेशा चलने लायक रहे। यह एक आदत अकेले ही बहुत सारी परेशानियाँ रोक देती है।

Tests पहले से चलें। अगर project में test suite है, तो agent का पहला reviewer वही है। उसे साफ़ कहें कि बदलाव के बाद test चलाए और fail होने पर आपको बताए, चुपचाप test बदलकर pass न करे। यह आख़िरी हिस्सा बहुत ज़रूरी है — कुछ agents परीक्षा पास करने के लिए परीक्षा बदल देते हैं।

Diff छोटा रखें। एक काम, एक branch, एक commit. 200 lines का diff इंसान ध्यान से पढ़ लेता है; 2,000 lines का diff वह Scroll करके approve कर देता है। अगर agent एक बार में बहुत बड़ा बदलाव कर रहा है, तो काम को छोटे हिस्सों में तोड़ें।

Insaan ka review रखें। Security, data access और business logic — ये तीन चीज़ें खुद देखें। Agent को नहीं पता कि इस table में customer के PAN number हैं या नहीं, और न ही यह कि यह function सिर्फ़ internal users के लिए है।

Secrets दूर रखें। env file, API keys और production credentials agent को न दें। ज़रूरत हो तो अलग test keys इस्तेमाल करें, और agent को बताएँ कि किन files को छूना मना है।

किस काम में कौन सा

छोटा बदलाव, वही file: editor autocomplete. दो नए functions, एक validation, एक छोटा CSS fix — यहाँ agent खोलना भी ज़रूरत से ज़्यादा है।

Multi-file bug fix: terminal agent. जब error का पता न हो और कई files देखनी हों, तो local agent सबसे तेज़ है क्योंकि वह असली environment में command चला सकता है।

साफ़ लिखा हुआ लंबा काम: cloud agent. Refactor, dependency update, test coverage बढ़ाना — ऐसे काम जिन्हें आप एक paragraph में समझा सकते हैं और जिनका नतीजा PR में देखा जा सकता है।

सीखना: chat. नए codebase को समझने के लिए "यह folder क्या करता है, request कहाँ से आती है" जैसे सवाल chat में सबसे अच्छे लगते हैं, क्योंकि आप जवाब पढ़कर आगे बढ़ते हैं।

अगर आप फोन से coding करना चाहते हैं, तो मैंने Claude Code को फोन पर चलाने की गाइड लिखी है — उसमें Termux और free models वाला पूरा setup है।

जहाँ agent पैसे की बर्बादी है

जब project में tests ही नहीं हैं। Agent बदलाव करेगा, आपको पता नहीं चलेगा कि क्या टूटा, और अगले हफ़्ते production में error आएगा। पहले test जोड़ें, फिर agent लाएँ।

जब codebase बहुत पुराना और बिना document है। Agent हर बार नए सिरे से अंदाज़ा लगाएगा। ऐसे में पहले एक छोटा "project map" लिखें — कौन सा folder क्या करता है — और उसे agent को दें। यह एक घंटे का काम बाद के हफ़्तों बचा देता है।

जब टीम में review की आदत नहीं है। Agent speed देगा, पर quality नहीं। बिना review के सिर्फ़ ज़्यादा code बनेगा, बेहतर code नहीं।

जब बजट का हिसाब नहीं है। Agent एक बार में कई model calls करता है — file पढ़ना, edit करना, test चलाना, error पढ़कर दोबारा कोशिश करना। एक छोटा काम 10 calls में खत्म हो सकता है, और एक भटका हुआ काम 60 calls में। इसलिए हर task पर एक सीमा तय करें: कितने steps, कितना समय, कितना खर्च। जब सीमा पूरी हो जाए, agent रुक जाए और आपको बताए कि कहाँ अटका — यही आदत बिल को नियंत्रण में रखती है।

Mera anubhav

मैंने सबसे पहले agent को बड़े काम पर लगाया — "पूरे project का authentication refactor कर दो". नतीजा यह आया कि 40 files बदलीं, कुछ ठीक, कुछ अधूरी, और मुझे पूरा diff पढ़ने में उतना ही समय लगा जितना खुद लिखने में लगता। उसके बाद मैंने तरीका बदला: एक बार में एक छोटा काम, पहले test, फिर agent, फिर diff. अब वही काम तीन गुना तेज़ होता है।

दूसरी बात जो मैंने सीखी: agent को context देना सबसे ज़्यादा फर्क लाता है। जब मैंने project की जड़ में एक छोटी file रखी जिसमें लिखा था कि कौन सी library इस्तेमाल होती है, कौन से naming rules हैं और कौन सी files छूनी नहीं हैं, तो agent की गलतियाँ आधी हो गईं। यह वही सोच है जो AI agents वाली guide में है — agent का quality उसके tools और instructions से तय होता है, model के नाम से नहीं।

तीसरी बात: agent से लिखवाया code पढ़ना एक अलग हुनर है। मैं अब diff में पहले वही देखता हूँ जो agent को नहीं पता — error handling, edge cases और permission checks. जो हिस्सा साफ़ दिख रहा है, उसे जल्दी पार कर देता हूँ। इस आदत से review का समय आधा हो गया।

नतीजा

Claude Code, Codex और Copilot तीन प्रतिद्वंद्वी नहीं, तीन जगहें हैं। Editor में autocomplete रोज़ का काम तेज़ करता है, terminal agent मुश्किल debugging और multi-file fix में काम आता है, और cloud agent उन साफ़ tasks के लिए है जिन्हें आप PR में बदल देना चाहते हैं। शुरुआत में एक चुनें, उसे छोटे कामों पर चलाएँ, और guardrails पहले बना लें — branch, tests, छोटा diff और अपना review. बाकी सब tool का update है।

अक्सर पूछे जाने वाले सवाल

क्या ये tools free हैं?

तीनों में free tier या paid plan अलग-अलग हैं और समय के साथ बदलते रहते हैं। खरीदने से पहले official pricing page देखें — plan, usage limit और model access वहीं साफ़ लिखा होता है।

क्या agent मेरा code बाहर भेजता है?

Terminal और editor tools आपके code के हिस्से model को भेजते हैं; cloud agent पूरा repo copy करता है। इसलिए company की policy पढ़ें और secret वाली files को बाहर रखें।

क्या agent मेरी नौकरी ले लेगा?

नहीं, पर उसका काम बदल देगा। लिखने से ज़्यादा पढ़ना, जाँचना और design तय करना — यही अब ज़्यादा मायने रखता है।

क्या मुझे सब कुछ agent से लिखवाना चाहिए?

नहीं। जो चीज़ आप खुद समझते हैं, उसे agent पर छोड़ने से सीखना रुक जाता है। नए concept पहले खुद लिखें, फिर agent से सुधार कराएँ।

सबसे ज़रूरी एक आदत कौन सी है?

Merge से पहले diff पढ़ना। यह एक आदत बाकी सब गलतियों का बड़ा हिस्सा रोक देती है।
