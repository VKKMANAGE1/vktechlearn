Data science में सबसे बड़ी उलझन यह नहीं है कि सीखना मुश्किल है — उलझन यह है कि सीखने के लिए सौ रास्ते दिखते हैं और कोई नहीं बताता कि पहले कौन सा। कोई कहता है Python से शुरू करो, कोई statistics से, कोई सीधे deep learning के course पर पैसे लगा देता है। नतीजा यह होता है कि छह महीने बाद बहुत सारे certificates हैं और एक भी ऐसा project नहीं जिसे interview में दिखाया जा सके।

इस guide में मैं वही क्रम बताऊँगा जो असली काम में चलता है — data science में भूमिकाएँ कौन-कौन सी हैं, skills का सही order, 90 दिन का plan, तीन portfolio projects, tools, interview का असली format, और वे छह गलतियाँ जो सबसे ज़्यादा समय बर्बाद करती हैं। भारत के job market को ध्यान में रखकर लिखा है, पर बुनियादी बातें हर जगह लागू होंगी।

छोटा जवाब: पहले SQL और data की सफ़ाई, फिर Excel/visualisation, फिर Python (pandas), फिर statistics, और machine learning सबसे आख़िर में। इस क्रम की वजह सीधी है — असली काम का 70% समय data निकालने और साफ़ करने में जाता है। जो इस हिस्से में मज़बूत है, उसे model का नाम भी याद रहता है; जो सिर्फ़ model सीखता है, वह पहले ही हफ़्ते में अटक जाता है।

Data science kya hai — aur teen alag roles

Data science का मतलब है data से ऐसा सवाल हल करना जो business के लिए मायने रखे — "कौन से customers जाने वाले हैं", "किस शहर में demand बढ़ रही है", "कौन सा discount सच में काम करता है". इसमें data निकालना, साफ़ करना, समझना, model बनाना और नतीजा समझाना — पाँचों आते हैं।

भारत में इस काम के तीन नाम मिलते हैं और उनका रोज़ का काम अलग होता है। Data analyst ज़्यादातर SQL और dashboards पर काम करता है — सवाल लेकर आता है और जवाब देता है। Data scientist उससे आगे prediction और experiment करता है। Data engineer वह ढाँचा बनाता है जिससे data साफ़ होकर आता है। शुरुआत में यह जानना ज़रूरी है कि आपको कौन सा काम पसंद है, क्योंकि तीनों की तैयारी अलग है।

Skills ka sahi kram

1. SQL — पहला हुनर

हर company का data किसी database में है और उसे निकालने का रास्ता SQL है। SELECT, WHERE, GROUP BY, JOIN और subquery — यह पाँच चीज़ें अच्छे से आ जाएँ तो आप 60% interview सवाल संभाल सकते हैं। इसे सीखने में दो हफ़्ते लगते हैं और फिर हर हफ़्ते practice चाहिए।

2. Excel या spreadsheet

Excel को पुराना मत समझें। छोटी companies में आज भी data spreadsheet में आता है, और pivot table बनाना सबसे तेज़ तरीका है किसी नए dataset को समझने का। यहाँ आप यह भी सीखते हैं कि data में क्या अजीब है — missing values, duplicate rows, अजीब dates.

3. Python — pandas के साथ

Python सीखें, पर पूरी language नहीं — सिर्फ़ वह हिस्सा जो data के काम आता है: variables, lists, dictionaries, loops, functions, और फिर pandas. pandas में read_csv, filter, groupby, merge और pivot — यही चार-पाँच operations 80% काम कर देते हैं।

4. Statistics — कम, पर सही

आपको सांख्यिकी की पूरी किताब नहीं चाहिए। इतना चाहिए: average और median का फर्क, distribution, standard deviation, correlation, sampling, और hypothesis test का मतलब। यह जानना ज़रूरी है क्योंकि गलत नतीजे अक्सर model की नहीं, सांख्यिकी की गलती से आते हैं — जैसे 30 rows पर बना conclusion. गहराई के लिए machine learning vs deep learning वाली guide पढ़ें।

5. Visualisation

Chart बनाना सीखें, पर सजावट नहीं — साफ़ communication. एक अच्छा chart 10 slides से ज़्यादा काम करता है। Excel, Power BI, Tableau या Python में matplotlib/plotly — कोई एक चुनें और उसमें अच्छे हो जाएँ।

6. Machine learning — आख़िर में

जब data साफ़ करना और सवाल बनाना आ जाए, तब ML शुरू करें। पहले linear regression और logistic regression, फिर decision tree और random forest. Neural network तभी, जब data image/text हो या table data की हद आ जाए।

तीन portfolio projects

1. साफ़ data वाला analysis. कोई public dataset लें — जैसे सरकारी data portal या Kaggle का कोई साफ़ dataset — और एक सवाल का जवाब दें: "किन राज्यों में कौन सा pattern है". इसमें SQL, सफ़ाई और 3 charts दिखें। सबसे ज़रूरी हिस्सा अंत में लिखा "5 बातें जो मुझे मिलीं" वाला हिस्सा है।

2. Prediction वाला project. Churn, price या delivery time — कुछ भी। पहले baseline बनाएँ, फिर दो models तुलना करें, और अंत में साफ़ लिखें कि model कहाँ गलत होता है। जो लोग सिर्फ़ accuracy लिखते हैं, उनका project अधूरा माना जाता है।

3. एक dashboard या छोटी app. Streamlit या Power BI में एक page जहाँ user filter बदलकर नतीजा देख सके। इससे पता चलता है कि आप काम को किसी और के इस्तेमाल लायक बना सकते हैं — यही चीज़ job में सबसे ज़्यादा मायने रखती है।

एक आदत जो बहुत मदद करती है — हर project के अंत में एक छोटा "अगर मुझे दो हफ़्ते और मिलते" वाला हिस्सा लिखें। इससे interviewer को दिखता है कि आप अपने काम की सीमा जानते हैं, और अगली बार क्या सुधारना है यह भी साफ़ रहता है।

हर project के साथ README लिखें: सवाल क्या था, data कहाँ से आया, क्या-क्या साफ़ किया, क्या नतीजा मिला, और क्या नहीं कर पाए। यही README interview में सबसे ज़्यादा पढ़ा जाता है।

Tools: कितने और कौन से

शुरुआत में चार tools काफ़ी हैं: एक SQL client, Excel या Google Sheets, Python (pandas + matplotlib), और Git. जब job मिल जाए, तब company के tools सीख लेंगे। नए tools की list बनाना सीखने का विकल्प नहीं है।

Git को शुरू से इस्तेमाल करें, भले ही अकेले काम कर रहे हों — Git और GitHub वाली guide में बुनियादी commands हैं। Interview में अक्सर पूछा जाता है कि आपका code कहाँ है; GitHub link इसका सबसे आसान जवाब है।

Salary ki reality

Salary के बारे में एक ईमानदार बात: कोई भी single number गलत होगा। वह शहर, company के size, role के नाम, आपके experience और interview के performance — पाँचों पर निर्भर करती है। जो लोग "data scientist ki salary itni hi hai" वाली table दिखाते हैं, वे अक्सर सबसे अच्छे cases को average बता देते हैं।

जो बात ज़्यादा भरोसेमंद है: analyst से scientist की तरफ़ जाने पर salary बढ़ती है, पर उससे ज़्यादा फर्क यह पड़ता है कि आप किस business problem का मालिक बन सकते हैं। जो इंसान "dashboard बनाता है" उससे ज़्यादा वह कमाता है जो "किस metric पर काम करना है यह तय करता है". इसलिए portfolio में सवाल चुनने की क्षमता दिखाएँ, सिर्फ़ tool नहीं।

Offer तुलना करते समय सिर्फ़ base salary न देखें — learning budget, team, manager और काम का असली scope भी देखें। पहले दो साल में सीखने की गति, salary के 10% से ज़्यादा मायने रखती है।

Interview kaise hota hai

ज़्यादातर data science interviews में चार हिस्से होते हैं। पहला — SQL का सवाल, जहाँ JOIN और window function आते हैं। दूसरा — case study, जहाँ कोई business सवाल दिया जाता है और आपको सोचकर बताना होता है कि data क्या चाहिए और कैसे नापेंगे। तीसरा — statistics या ML का बुनियादी सवाल, जैसे overfitting क्या है या precision और recall में कब कौन सा चुनेंगे। चौथा — आपका पिछला project, जहाँ वे पूछते हैं कि क्या गलत हुआ और आपने क्या सीखा।

Interview की तैयारी में एक चीज़ बहुत मदद करती है — अपने ही project पर तीन सवाल खुद से पूछना: यह सवाल क्यों मायने रखता था, मैंने यह तरीका क्यों चुना, और अगर data दुगना होता तो क्या बदलता। इन तीनों के जवाब तैयार होने पर interview बातचीत जैसा लगता है, पूछताछ जैसा नहीं। साथ में एक छोटा notebook रखें जिसमें हर project के numbers और सीमाएँ लिखी हों; मुँह से याद करने की कोशिश में लोग गोल-मोल जवाब दे देते हैं।

चौथे हिस्से में ईमानदारी सबसे ज़्यादा काम आती है। "मेरे model का score 84% था, पर data में पुराने महीने कम थे इसलिए मुझे भरोसा सीमित है" — यह जवाब "मेरा model perfect था" से बहुत बेहतर माना जाता है।

छह गलतियाँ जो समय बर्बाद करती हैं

1. Certificates इकट्ठा करना। दस courses से ज़्यादा एक पूरा project मायने रखता है। Course देखना सीखना नहीं है।

2. सीधे deep learning से शुरू करना। जब SQL नहीं आती, तो neural network किसी काम का नहीं।

3. Data साफ़ करने को छोटा काम समझना। असली project में 70% समय यहीं जाता है; इसे skip करने से नतीजे गलत आते हैं।

4. सिर्फ़ accuracy देखना। असंतुलित data में 95% accuracy वाला model बेकार हो सकता है। Precision, recall और confusion matrix देखें।

5. नतीजा समझाना न सीखना। जो analysis कोई नहीं समझता, वह analysis किसी काम की नहीं। एक page में लिखने की आदत डालें।

6. अकेले सीखना। एक study group या दोस्त रखें जिसे आप हर हफ़्ते अपना काम दिखाएँ। सवाल पूछने से सीखना दुगना तेज़ होता है।

Mera anubhav

मैंने शुरुआत में तीन ML courses पूरे किए और फिर भी एक असली dataset देखकर अटक गया, क्योंकि उसमें 40% cells खाली थीं और dates तीन अलग formats में थीं। उस दिन समझ आया कि जो courses मैंने किए, वे साफ़ data पर थे — और असली दुनिया साफ़ नहीं होती।

उसके बाद मैंने एक हफ़्ता सिर्फ़ data साफ़ करने पर लगाया — missing values कैसे भरें, duplicates कैसे पकड़ें, कौन सा column भरोसेमंद नहीं। यही हफ़्ता मेरे पूरे सीखने का सबसे कीमती हिस्सा बना। आज जब कोई पूछता है "कहाँ से शुरू करूँ", तो मैं कहता हूँ — एक गंदा dataset लो और उसे साफ़ करो।

दूसरी बात: portfolio में "क्या बनाया" से ज़्यादा "क्यों बनाया" लिखें। जिस project में सवाल साफ़ है, वह तकनीकी रूप से सादा होने पर भी चुना जाता है। जिसमें सिर्फ़ 92% accuracy लिखी है, वह किसी को याद नहीं रहता।

नतीजा

Data science की तैयारी एक क्रम है, न कि tools की list: SQL, spreadsheet, Python, statistics, visualisation, और फिर ML. नब्बे दिन में अगर आपने चार छोटे काम पूरे किए और एक अच्छा README लिखा, तो आप उन लोगों से आगे हैं जिन्होंने साल भर courses देखे। शुरुआत आज एक dataset और एक सवाल से करें — बाकी सब उसी से निकल आएगा।

अक्सर पूछे जाने वाले सवाल

क्या data science के लिए engineering degree ज़रूरी है?

नहीं। Companies skills और project देखती हैं। गणित या statistics की समझ ज़रूरी है, पर degree का नाम नहीं।

क्या Python के बिना data science हो सकती है?

Analyst roles में SQL और Excel से बहुत काम हो जाता है। Scientist roles में Python या R चाहिए, क्योंकि model और cleaning वहीं होती है।

कितने projects काफ़ी हैं?

तीन अच्छे projects दस औसत projects से बेहतर हैं। हर project में सवाल, data, तरीका और नतीजा साफ़ लिखा हो।

क्या maths weak हो तो रास्ता बंद है?

नहीं। Basic statistics और logic मज़बूत करें, और जो समझ न आए उसे simulation या छोटे examples से समझें। रोज़ का काम इतना गहरा गणित माँगता ही नहीं।

Fresher को पहली job कैसे मिलती है?

Internship, freelance छोटे projects और referral — तीनों साथ चलाएँ। Portfolio link के साथ approach करें, सिर्फ़ resume से नहीं।
