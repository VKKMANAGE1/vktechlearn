Chapter 9 टेस्ट — 20 सवाल

20 प्रश्न·हर सवाल 1 अंक·उत्तर अंत में

पहले सारे 20 के जवाब कागज़ पर लिखें, फिर नीचे उत्तर-कुंजी से जाँचें — 16 या ज़्यादा सही मतलब चैप्टर ठीक से समझ आ गया है।

  1. Pentest का पहला कदम क्या है?

    1. Scoping और लिखित अनुमति
    2. Port scan
    3. Exploit
    4. Report

  2. Rules of Engagement में क्या तय होता है?

    1. कौन सी techniques allowed हैं और कब
    2. सिर्फ़ फ़ीस
    3. सिर्फ़ report का रंग
    4. सिर्फ़ टीम का नाम

  3. PoC कितना होना चाहिए?

    1. सिर्फ़ ज़रूरी proof
    2. पूरा database dump
    3. सारे passwords
    4. server बंद

  4. Finding लिखते समय क्या शामिल करें?

    1. Title, severity, location, impact, fix
    2. सिर्फ़ screenshot
    3. सिर्फ़ नाम
    4. सिर्फ़ tool

  5. Cleanup में क्या किया जाता है?

    1. बनाई फ़ाइलें, accounts और settings हटाना
    2. नए users जोड़ना
    3. Server बंद करना
    4. Data कॉपी करना

  6. Sign-off क्यों ज़रूरी है?

    1. Client से पुष्टि कि testing पूरी और system सामान्य
    2. बिल भेजने के लिए
    3. Report छिपाने के लिए
    4. नई फ़ीस के लिए

  7. Framework में module का सिद्धांत क्या है?

    1. एक module, एक काम
    2. सब कुछ एक file में
    3. कोई function नहीं
    4. सिर्फ़ GUI

  8. argparse framework में किस काम आता है?

    1. Command-line options
    2. Hashing
    3. Chart
    4. PDF

  9. Config file का फ़ायदा क्या है?

    1. Settings बिना code बदले बदलना
    2. Code तेज़ करना
    3. Report बनाना
    4. Wi-Fi जोड़ना

  10. JSON output क्यों रखें?

    1. Report और analysis आसान
    2. File बड़ी करने के लिए
    3. Code छिपाने के लिए
    4. सिर्फ़ सुंदरता

  11. Framework के safe default क्या होने चाहिए?

    1. धीमे, सीमित threads और rate limit
    2. तेज़, unlimited threads
    3. कोई timeout नहीं
    4. सारे targets

  12. Scope check हर run में क्यों?

    1. गलत target पर testing रोकने के लिए
    2. Speed के लिए
    3. Report के लिए
    4. कुछ नहीं

  13. Logging framework में क्यों रखें?

    1. क्या हुआ, कब हुआ — रिकॉर्ड के लिए
    2. File छोटी करने के लिए
    3. Speed के लिए
    4. GUI के लिए

  14. Version control का फ़ायदा क्या है?

    1. पुराना काम करने वाला version वापस पाना
    2. Report अपने आप बनना
    3. Speed बढ़ना
    4. Wi-Fi जुड़ना

  15. Automation में rate limit क्यों?

    1. Target पर अनचाहा भार न पड़े
    2. Tool तेज़ हो
    3. Report छोटी हो
    4. कोई कारण नहीं

  16. End-to-end pentest में अंतिम चरण क्या है?

    1. Report और sign-off
    2. Recon
    3. Scanning
    4. Exploitation

  17. Tool का output बिना verify भेजना क्यों ग़लत है?

    1. False positive report में जा सकते हैं
    2. Report लंबी होती है
    3. Tool धीमा होता है
    4. कोई कारण नहीं

  18. Cleanup के बाद क्या जाँचें?

    1. System पहले जैसा है या नहीं
    2. नए ports
    3. Wi-Fi password
    4. Logo

  19. Testing के दौरान critical finding मिले तो?

    1. तुरंत तय contact को बताएँ
    2. Report के अंत तक रोकें
    3. किसी को न बताएँ
    4. सोशल मीडिया पर डालें

  20. Professional pentest की सबसे बड़ी पहचान क्या है?

    1. अनुशासित process और साफ़ report
    2. सबसे ज़्यादा tools
    3. सबसे तेज़ scan
    4. सबसे लंबा report

उत्तर-कुंजी

  1. Q1 — (a) Scoping और लिखित अनुमति
    बिना scope और अनुमति testing शुरू नहीं होती।
  2. Q2 — (a) कौन सी techniques allowed हैं और कब
    इसमें समय, banned techniques और communication तय होते हैं।
  3. Q3 — (a) सिर्फ़ ज़रूरी proof
    कम से कम असर वाला proof पर्याप्त और सुरक्षित है।
  4. Q4 — (a) Title, severity, location, impact, fix
    यही format developer के लिए सबसे उपयोगी है।
  5. Q5 — (a) बनाई फ़ाइलें, accounts और settings हटाना
    Testing के बाद system सामान्य हालत में लौटाना ज़रूरी है।
  6. Q6 — (a) Client से पुष्टि कि testing पूरी और system सामान्य
    यह engagement बंद करने का औपचारिक हिस्सा है।
  7. Q7 — (a) एक module, एक काम
    अलग modules पढ़ने, test करने और बदलने में आसान होते हैं।
  8. Q8 — (a) Command-line options
    इससे module और target command line से चुने जाते हैं।
  9. Q9 — (a) Settings बिना code बदले बदलना
    timeout, threads और output path config में रखें।
  10. Q10 — (a) Report और analysis आसान
    एक ही structure से आगे processing होती है।
  11. Q11 — (a) धीमे, सीमित threads और rate limit
    गलती से production पर भार न पड़े।
  12. Q12 — (a) गलत target पर testing रोकने के लिए
    यह एक बुनियादी safety control है।
  13. Q13 — (a) क्या हुआ, कब हुआ — रिकॉर्ड के लिए
    बाद में समस्या या सबूत समझने में मदद मिलती है।
  14. Q14 — (a) पुराना काम करने वाला version वापस पाना
    Git से बदलाव track और rollback होते हैं।
  15. Q15 — (a) Target पर अनचाहा भार न पड़े
    तेज़ requests से service धीमी या बंद हो सकती है।
  16. Q16 — (a) Report और sign-off
    काम report और client की पुष्टि पर पूरा होता है।
  17. Q17 — (a) False positive report में जा सकते हैं
    हर finding हाथ से जाँची जानी चाहिए।
  18. Q18 — (a) System पहले जैसा है या नहीं
    Client के systems में कोई बदलाव न छूटे।
  19. Q19 — (a) तुरंत तय contact को बताएँ
    Rules of Engagement में emergency contact तय होता है।
  20. Q20 — (a) अनुशासित process और साफ़ report
    Process और documentation ही असली मूल्य हैं।
