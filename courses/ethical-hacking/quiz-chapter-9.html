Chapter 9 टेस्ट — 20 सवाल

20 प्रश्न·हर सवाल 1 अंक·उत्तर अंत में

हर सवाल का एक विकल्प चुनें और नीचे जवाब जमा करें दबाएँ — स्कोर और हर सवाल की व्याख्या तुरंत दिखेगी। 16 या ज़्यादा सही मतलब चैप्टर ठीक से समझ आ गया है।

  1. Pentest का पहला कदम क्या है?

    सही उत्तर: Scoping और लिखित अनुमति — बिना scope और अनुमति testing शुरू नहीं होती।

  2. Rules of Engagement में क्या तय होता है?

    सही उत्तर: कौन सी techniques allowed हैं और कब — इसमें समय, banned techniques और communication तय होते हैं।

  3. PoC कितना होना चाहिए?

    सही उत्तर: सिर्फ़ ज़रूरी proof — कम से कम असर वाला proof पर्याप्त और सुरक्षित है।

  4. Finding लिखते समय क्या शामिल करें?

    सही उत्तर: Title, severity, location, impact, fix — यही format developer के लिए सबसे उपयोगी है।

  5. Cleanup में क्या किया जाता है?

    सही उत्तर: बनाई फ़ाइलें, accounts और settings हटाना — Testing के बाद system सामान्य हालत में लौटाना ज़रूरी है।

  6. Sign-off क्यों ज़रूरी है?

    सही उत्तर: Client से पुष्टि कि testing पूरी और system सामान्य — यह engagement बंद करने का औपचारिक हिस्सा है।

  7. Framework में module का सिद्धांत क्या है?

    सही उत्तर: एक module, एक काम — अलग modules पढ़ने, test करने और बदलने में आसान होते हैं।

  8. argparse framework में किस काम आता है?

    सही उत्तर: Command-line options — इससे module और target command line से चुने जाते हैं।

  9. Config file का फ़ायदा क्या है?

    सही उत्तर: Settings बिना code बदले बदलना — timeout, threads और output path config में रखें।

  10. JSON output क्यों रखें?

    सही उत्तर: Report और analysis आसान — एक ही structure से आगे processing होती है।

  11. Framework के safe default क्या होने चाहिए?

    सही उत्तर: धीमे, सीमित threads और rate limit — गलती से production पर भार न पड़े।

  12. Scope check हर run में क्यों?

    सही उत्तर: गलत target पर testing रोकने के लिए — यह एक बुनियादी safety control है।

  13. Logging framework में क्यों रखें?

    सही उत्तर: क्या हुआ, कब हुआ — रिकॉर्ड के लिए — बाद में समस्या या सबूत समझने में मदद मिलती है।

  14. Version control का फ़ायदा क्या है?

    सही उत्तर: पुराना काम करने वाला version वापस पाना — Git से बदलाव track और rollback होते हैं।

  15. Automation में rate limit क्यों?

    सही उत्तर: Target पर अनचाहा भार न पड़े — तेज़ requests से service धीमी या बंद हो सकती है।

  16. End-to-end pentest में अंतिम चरण क्या है?

    सही उत्तर: Report और sign-off — काम report और client की पुष्टि पर पूरा होता है।

  17. Tool का output बिना verify भेजना क्यों ग़लत है?

    सही उत्तर: False positive report में जा सकते हैं — हर finding हाथ से जाँची जानी चाहिए।

  18. Cleanup के बाद क्या जाँचें?

    सही उत्तर: System पहले जैसा है या नहीं — Client के systems में कोई बदलाव न छूटे।

  19. Testing के दौरान critical finding मिले तो?

    सही उत्तर: तुरंत तय contact को बताएँ — Rules of Engagement में emergency contact तय होता है।

  20. Professional pentest की सबसे बड़ी पहचान क्या है?

    सही उत्तर: अनुशासित process और साफ़ report — Process और documentation ही असली मूल्य हैं।
