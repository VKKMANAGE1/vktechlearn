Chapter 7 · Network Security और Defense

Network Hardening और Incident Response

लेसन 14 / 20·~7 मिनट·by Vïnâý Kúshwâhå

हमला पकड़ना आधा काम है; उसे रोकना और असर कम करना बाकी आधा। Network hardening का मतलब है attack surface छोटा करना — कम खुले ports, मज़बूत configuration, अपडेटेड software और साफ़ logging।

Hardening के मुख्य कदम

  1. Inventory: कौन से devices और services नेटवर्क पर हैं — बिना सूची के सुरक्षा संभव नहीं।
  2. Patch management: OS, firmware और applications के updates समय पर लगाएँ।
  3. Least privilege: हर user और service को सिर्फ़ ज़रूरी अधिकार दें।
  4. Firewall rules: जो चाहिए वही allow करें, बाकी बंद — default deny।
  5. Logging: login, firewall और application logs केंद्र में इकट्ठे करें।
  6. Backups: 3-2-1 नियम — तीन copy, दो माध्यम, एक offline।

Python से configuration जाँच

कई devices का configuration बार-बार जाँचना पड़ता है। छोटा script इसे आसान बनाता है:

import subprocess

checks = {
    "firewall": ["ufw", "status"],
    "listening": ["ss", "-tuln"],
}

for name, cmd in checks.items():
    print("==", name)
    print(subprocess.run(cmd, capture_output=True, text=True).stdout)

इसी तरह यह भी जाँचा जा सकता है कि कोई अनचाहा port तो नहीं खुला, या firewall चालू है या नहीं। Automation से मानवीय भूल कम होती है।

Incident Response के चरण

चरणकाम
Preparationplan, contacts, tools पहले से तैयार
Identificationक्या हुआ, कब हुआ, कौन से systems प्रभावित
Containmentअसर फैलने से रोकना — network से अलग करना
Eradicationmalware हटाना, कमज़ोरी ठीक करना
Recoveryसाफ़ backup से बहाली, निगरानी
Lessons learnedreport और सुधार के कदम

Containment में जल्दबाज़ी न करें — पहले सबूत सुरक्षित करें, फिर मशीन बंद या अलग करें। वरना memory में मौजूद जानकारी खो सकती है।

Forensic data जुटाना

  • Volatile: चल रहे processes, network connections, logged-in users — पहले यही लें।
  • Disk: log files, recently modified files, scheduled tasks।
  • Timeline: घटनाओं का क्रम — कौन सी फ़ाइल कब बनी।
  • Hashes: सबूत की अखंडता साबित करने के लिए।
import psutil

for p in psutil.process_iter(["pid", "name", "username"]):
    print(p.info)

यह snapshot बताता है कि उस समय कौन से programs चल रहे थे — incident report का ज़रूरी हिस्सा।

याद रखें
  • Hardening = कम surface, updates, least privilege, logging
  • Firewall में default deny
  • Incident response: contain पहले, फिर eradicate और recover
  • सबूत पहले सुरक्षित करें, फिर मशीन अलग करें
Practical — 10 मिनट

अपने लैपटॉप पर खुले ports की सूची देखें और लिखें कि कौन सा ज़रूरी है। जो भी ज़रूरी नहीं, उसे बंद करने का तरीका नोट करें।
