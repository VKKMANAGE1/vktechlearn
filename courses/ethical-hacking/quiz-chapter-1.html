Chapter 1 · Ethical Hacking का परिचय

Chapter 1 टेस्ट — 20 सवाल

20 प्रश्न·हर सवाल 1 अंक·उत्तर अंत में

पहले सारे 20 के जवाब कागज़ पर लिखें, फिर नीचे उत्तर-कुंजी से जाँचें — 16 या ज़्यादा सही मतलब चैप्टर ठीक से समझ आ गया है।

  1. Ethical hacking का सबसे सही अर्थ क्या है?

    1. अनुमति के बिना system जाँचना
    2. लिखित अनुमति के साथ सुरक्षा की जाँच करना
    3. वेबसाइट हैक करना
    4. एंटीवायरस बेचना

  2. White hat hacker किसे कहते हैं?

    1. जो बिना अनुमति घुसता है
    2. जो अनुमति लेकर कमज़ोरी ढूँढकर बताता है
    3. जो वायरस बनाता है
    4. जो पासवर्ड बेचता है

  3. Black hat hacker की पहचान क्या है?

    1. लिखित अनुमति लेना
    2. बिना अनुमति नुक़सान या फ़ायदे के लिए घुसना
    3. सिर्फ़ रिपोर्ट लिखना
    4. सिर्फ़ lab में काम करना

  4. Grey hat hacker के बारे में कौन सी बात सही है?

    1. वह पूरी तरह कानूनी है
    2. वह बिना अनुमति काम करता है, चाहे इरादा अच्छा हो
    3. वह सिर्फ़ सरकार के लिए काम करता है
    4. वह कोई testing नहीं करता

  5. Penetration test का पहला चरण क्या होता है?

    1. Exploitation
    2. Scoping और लिखित permission
    3. Reporting
    4. Port scanning

  6. Scope document में क्या साफ़ होना चाहिए?

    1. केवल कंपनी का logo
    2. कौन से systems, कौन सी techniques और कब तक
    3. सिर्फ़ फ़ीस
    4. सिर्फ़ टीम के नाम

  7. Reconnaissance चरण का मक़सद क्या है?

    1. System में घुसना
    2. Target की जानकारी इकट्ठी करना
    3. Report लिखना
    4. Data मिटाना

  8. Exploitation के दौरान क्या ध्यान रखना चाहिए?

    1. जितना ज़्यादा नुक़सान हो उतना अच्छा
    2. सबसे कम नुक़सान वाला proof देना
    3. production बंद कर देना
    4. सारा data डाउनलोड करना

  9. Post-exploitation में क्या किया जाता है?

    1. मिले access का असर और सीमा जाँचना
    2. वेबसाइट डिलीट करना
    3. नए हमलावर को बुलाना
    4. बिल भेजना

  10. Testing के बाद cleanup क्यों ज़रूरी है?

    1. बिल कम करने के लिए
    2. बनाई गई files/accounts हटाकर system सामान्य करने के लिए
    3. report छिपाने के लिए
    4. scope बढ़ाने के लिए

  11. Responsible disclosure का मतलब क्या है?

    1. कमज़ोरी पहले सार्वजनिक करना
    2. पहले मालिक को बताना, फिर उनके timeline के हिसाब से आगे बढ़ना
    3. किसी को न बताना
    4. कमज़ोरी बेचना

  12. किसी दूसरे के Wi-Fi पर बिना अनुमति scan करना क्या है?

    1. सामान्य बात
    2. कानून का उल्लंघन
    3. Bug bounty
    4. Research

  13. NDA का काम क्या है?

    1. Testing की अनुमति देना
    2. मिली जानकारी गोपनीय रखने का वादा
    3. फ़ीस तय करना
    4. Report लिखना

  14. Pentest का अंतिम और सबसे ज़रूरी output क्या है?

    1. Tool की सूची
    2. Report जिसमें finding और fix हों
    3. Screenshot का folder
    4. नया server

  15. अगर testing के दौरान scope से बाहर कोई system मिले तो?

    1. उसे भी test कर लें
    2. न छुएँ और client को बताएँ
    3. उसे डिलीट करें
    4. उसका data ले लें

  16. Ethical hacking का फ़ायदा क्या नहीं है?

    1. हमले से पहले सुधार
    2. Compliance
    3. ग्राहक का भरोसा
    4. बिना अनुमति data बेचना

  17. Security testing के लिए सबसे सुरक्षित जगह कौन सी है?

    1. Production server
    2. अपनी isolated lab VM
    3. किसी का घर
    4. सार्वजनिक Wi-Fi

  18. Vulnerability assessment और penetration test में मुख्य फ़र्क़ क्या है?

    1. दोनों एक ही हैं
    2. Assessment कमज़ोरियाँ खोजता है, pentest उनका असर साबित करता है
    3. Pentest में report नहीं होती
    4. Assessment सिर्फ़ hardware के लिए है

  19. Ethical hacker की ज़िम्मेदारी में क्या शामिल नहीं है?

    1. अनुमति लेना
    2. Data गोपनीय रखना
    3. Report देना
    4. कमज़ोरी को सार्वजनिक नीलामी में बेचना

  20. Hacking lifecycle का सही क्रम कौन सा है?

    1. Recon → Scanning → Exploitation → Reporting
    2. Reporting → Recon → Scanning → Exploitation
    3. Exploitation → Recon → Reporting → Scanning
    4. Scanning → Reporting → Recon → Exploitation

उत्तर-कुंजी

  1. Q1 — (b) लिखित अनुमति के साथ सुरक्षा की जाँच करना
    Ethical hacking में मालिक की अनुमति और तय scope के भीतर ही testing होती है।
  2. Q2 — (b) जो अनुमति लेकर कमज़ोरी ढूँढकर बताता है
    White hat hacking कानूनी होती है और इरादा सुधार का होता है।
  3. Q3 — (b) बिना अनुमति नुक़सान या फ़ायदे के लिए घुसना
    Black hat बिना अनुमति घुसकर चोरी या नुक़सान करता है — यह अपराध है।
  4. Q4 — (b) वह बिना अनुमति काम करता है, चाहे इरादा अच्छा हो
    इरादा अच्छा होने पर भी बिना अनुमति access ग़ैरकानूनी रहता है।
  5. Q5 — (b) Scoping और लिखित permission
    बिना scope और अनुमति के कोई testing शुरू नहीं होती।
  6. Q6 — (b) कौन से systems, कौन सी techniques और कब तक
    Scope से तय होता है कि testing कहाँ तक जाएगी और क्या मना है।
  7. Q7 — (b) Target की जानकारी इकट्ठी करना
    Recon में domains, IP, tech stack जैसी जानकारी जुटाई जाती है।
  8. Q8 — (b) सबसे कम नुक़सान वाला proof देना
    PoC का मक़सद कमज़ोरी साबित करना है, नुक़सान करना नहीं।
  9. Q9 — (a) मिले access का असर और सीमा जाँचना
    Post-exploitation में देखा जाता है कि access से कितना जोखिम बनता है।
  10. Q10 — (b) बनाई गई files/accounts हटाकर system सामान्य करने के लिए
    Cleanup के बिना client के system में अनचाहे changes रह जाते हैं।
  11. Q11 — (b) पहले मालिक को बताना, फिर उनके timeline के हिसाब से आगे बढ़ना
    पहले affected party को मौक़ा देना responsible disclosure है।
  12. Q12 — (b) कानून का उल्लंघन
    बिना अनुमति किसी के नेटवर्क पर testing अपराध है।
  13. Q13 — (b) मिली जानकारी गोपनीय रखने का वादा
    Non-Disclosure Agreement से client की जानकारी गुप्त रखने की शर्त होती है।
  14. Q14 — (b) Report जिसमें finding और fix हों
    Report से ही organization सुधार कर पाता है।
  15. Q15 — (b) न छुएँ और client को बताएँ
    Scope से बाहर जाना अनुमति तोड़ना है; नई अनुमति चाहिए।
  16. Q16 — (d) बिना अनुमति data बेचना
    Data बेचना अपराध है, ethical hacking का हिस्सा नहीं।
  17. Q17 — (b) अपनी isolated lab VM
    Lab VM में ग़लती का असर सीमित रहता है और snapshot से वापस जा सकते हैं।
  18. Q18 — (b) Assessment कमज़ोरियाँ खोजता है, pentest उनका असर साबित करता है
    Assessment सूची बनाता है; pentest नियंत्रित तरीके से exploit करके जोखिम दिखाता है।
  19. Q19 — (d) कमज़ोरी को सार्वजनिक नीलामी में बेचना
    कमज़ोरी बेचना या सार्वजनिक करना professional और कानूनी नियमों के खिलाफ़ है।
  20. Q20 — (a) Recon → Scanning → Exploitation → Reporting
    पहले जानकारी, फिर scanning, फिर नियंत्रित exploitation और अंत में report।
