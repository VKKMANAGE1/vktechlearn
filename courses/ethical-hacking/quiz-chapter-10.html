Chapter 10 टेस्ट — 20 सवाल

20 प्रश्न·हर सवाल 1 अंक·उत्तर अंत में

पहले सारे 20 के जवाब कागज़ पर लिखें, फिर नीचे उत्तर-कुंजी से जाँचें — 16 या ज़्यादा सही मतलब चैप्टर ठीक से समझ आ गया है।

  1. Ethical hacking में सबसे ज़रूरी चीज़ क्या है?

    1. लिखित अनुमति
    2. नया laptop
    3. तेज़ internet
    4. बड़ा monitor

  2. भारत में computer अपराध मुख्य रूप से किस कानून के तहत आते हैं?

    1. IT Act, 2000
    2. Companies Act
    3. Motor Vehicle Act
    4. RTI Act

  3. Permission letter में क्या शामिल होना चाहिए?

    1. Scope, समय, allowed techniques, signature
    2. सिर्फ़ कंपनी का नाम
    3. सिर्फ़ फ़ीस
    4. सिर्फ़ ईमेल

  4. Scope से बाहर system मिलने पर क्या करें?

    1. न छुएँ और client को बताएँ
    2. उसे भी test करें
    3. उसका data लें
    4. उसे बंद करें

  5. NDA का मतलब क्या है?

    1. Non-Disclosure Agreement
    2. New Data Access
    3. Network Defense Application
    4. National Digital Act

  6. Responsible disclosure का सही तरीका क्या है?

    1. पहले कंपनी को सूचित करना
    2. पहले Twitter पर
    3. पहले बेचना
    4. किसी को न बताना

  7. Bug bounty में क्या मानना ज़रूरी है?

    1. Scope और program rules
    2. सिर्फ़ reward
    3. कोई नियम नहीं
    4. सिर्फ़ public disclosure

  8. DPDP Act किससे संबंधित है?

    1. Personal data protection
    2. Wi-Fi speed
    3. Printer drivers
    4. Cable standards

  9. Client का data testing के बाद क्या करें?

    1. सुरक्षित तरीके से मिटाएँ
    2. अपने पास रखें
    3. बेच दें
    4. सार्वजनिक करें

  10. Report का पहला हिस्सा क्या होना चाहिए?

    1. Executive summary
    2. सारे screenshots
    3. टूल की सूची
    4. Appendix

  11. Severity तय करते समय क्या देखें?

    1. Technical असर और business impact
    2. सिर्फ़ tool का score
    3. सिर्फ़ file size
    4. सिर्फ़ समय

  12. अच्छी finding में क्या नहीं होना चाहिए?

    1. दोषी व्यक्ति पर व्यक्तिगत आरोप
    2. Proof
    3. Impact
    4. Fix

  13. Screenshot में क्या छिपाना चाहिए?

    1. Password, token और personal data
    2. सिर्फ़ logo
    3. सिर्फ़ तारीख
    4. कुछ नहीं

  14. Remediation सुझाते समय क्या ध्यान रखें?

    1. व्यावहारिक और प्राथमिकता के क्रम में
    2. सिर्फ़ नया software खरीदना
    3. कुछ न सुझाना
    4. सिर्फ़ blame

  15. Sign-off का मक़सद क्या है?

    1. Testing की समाप्ति की लिखित पुष्टि
    2. नई फ़ीस
    3. Report छिपाना
    4. नया scope

  16. Security में करियर के लिए क्या सबसे ज़्यादा मदद करता है?

    1. Practical labs और portfolio
    2. सिर्फ़ certificates
    3. सिर्फ़ books
    4. सिर्फ़ YouTube

  17. SOC analyst का मुख्य काम क्या है?

    1. Alerts monitor और investigate करना
    2. वेबसाइट डिज़ाइन
    3. प्रिंटर ठीक करना
    4. बिल बनाना

  18. OWASP Top 10 क्या है?

    1. Web app के आम जोखिमों की सूची
    2. एक programming language
    3. एक firewall
    4. एक certification

  19. बिना अनुमति किसी के system पर testing का नतीजा क्या हो सकता है?

    1. जुर्माना और जेल
    2. कुछ नहीं
    3. सिर्फ़ warning
    4. reward

  20. एक अच्छे ethical hacker की सबसे बड़ी खूबी क्या है?

    1. ईमानदारी और ज़िम्मेदारी
    2. सबसे ज़्यादा tools
    3. सबसे तेज़ laptop
    4. सबसे लंबा report

उत्तर-कुंजी

  1. Q1 — (a) लिखित अनुमति
    अनुमति के बिना testing कानून का उल्लंघन है।
  2. Q2 — (a) IT Act, 2000
    IT Act unauthorized access और data से जुड़े अपराध cover करता है।
  3. Q3 — (a) Scope, समय, allowed techniques, signature
    यही document testing की सीमा तय करता है।
  4. Q4 — (a) न छुएँ और client को बताएँ
    नई अनुमति के बिना scope बढ़ाना ग़लत है।
  5. Q5 — (a) Non-Disclosure Agreement
    यह मिली जानकारी गोपनीय रखने की शर्त है।
  6. Q6 — (a) पहले कंपनी को सूचित करना
    कंपनी को सुधार का मौक़ा मिलना चाहिए।
  7. Q7 — (a) Scope और program rules
    Scope से बाहर जाना rules तोड़ना है।
  8. Q8 — (a) Personal data protection
    यह भारत का data protection कानून है।
  9. Q9 — (a) सुरक्षित तरीके से मिटाएँ
    Data handling agreement के हिसाब से मिटाना चाहिए।
  10. Q10 — (a) Executive summary
    Management को एक पेज में जोखिम समझ आना चाहिए।
  11. Q11 — (a) Technical असर और business impact
    Business impact से असली प्राथमिकता तय होती है।
  12. Q12 — (a) दोषी व्यक्ति पर व्यक्तिगत आरोप
    Report समस्या और समाधान पर होनी चाहिए।
  13. Q13 — (a) Password, token और personal data
    Sensitive data report में नहीं जाना चाहिए।
  14. Q14 — (a) व्यावहारिक और प्राथमिकता के क्रम में
    Team को ऐसा fix चाहिए जो लागू हो सके।
  15. Q15 — (a) Testing की समाप्ति की लिखित पुष्टि
    इससे engagement औपचारिक रूप से बंद होता है।
  16. Q16 — (a) Practical labs और portfolio
    Hands-on experience और documented work भरोसा बनाते हैं।
  17. Q17 — (a) Alerts monitor और investigate करना
    SOC team security events पर नज़र रखती है।
  18. Q18 — (a) Web app के आम जोखिमों की सूची
    यह web security की बुनियादी समझ देता है।
  19. Q19 — (a) जुर्माना और जेल
    IT Act के तहत सज़ा हो सकती है।
  20. Q20 — (a) ईमानदारी और ज़िम्मेदारी
    भरोसा ही इस पेशे की नींव है।
