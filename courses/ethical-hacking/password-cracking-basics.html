Password Cracking — Brute Force, Dictionary और Hashing

लेसन 9 / 20·~6 मिनट·by Vïnâý Kúshwâhå

Password ही ज़्यादातर breaches की शुरुआत होती है। इस लेसन में देखेंगे कि password store कैसे होते हैं, brute force और dictionary attack क्या हैं, और एक मज़बूत password असल में कैसे बचता है। सारी practice अपने lab और अपने ही test accounts पर।

Password प्लेन text में सेव नहीं होते

अच्छी वेबसाइट password को सीधे नहीं रखती; उसका hash बनाकर रखती है। Hash एक one-way function है — "hello" से hash बन जाता है, पर hash से "hello" वापस नहीं निकलता। Login के समय टाइप किए password का hash बनाकर stored hash से मिलाया जाता है।

import hashlib

h = hashlib.sha256("hello123".encode()).hexdigest()
print(h)

SHA-256 तेज़ है, इसलिए password के लिए अकेला ठीक नहीं। असली systems bcrypt, scrypt या Argon2 जैसे slow hash + salt इस्तेमाल करते हैं, जिससे एक-एक guess महँगा पड़े।

Salt क्या है

Salt एक random value है जो हर password के hash में जोड़ी जाती है। इससे एक जैसे passwords के भी अलग hash बनते हैं और precomputed tables (rainbow tables) बेकार हो जाती हैं। अच्छे systems में salt हर user के लिए अलग होता है।

Brute force और dictionary attack

  • Brute force: हर संभव combination try करना। छोटे password पर तेज़, लंबे password पर लगभग असंभव।
  • Dictionary attack: आम passwords और शब्दों की सूची try करना — जैसे password123, cricket, iloveyou।
  • Rule-based: dictionary शब्दों में अंक और symbol जोड़कर variants बनाना — "password" → "P@ssw0rd1"।
  • Credential stuffing: किसी और breach के leaked email-password जोड़े दूसरी साइट पर try करना — इसलिए हर साइट पर अलग password ज़रूरी।

क्या password असल में मज़बूत है

Passwordसमस्या
123456सबसे आम सूची में
Rahul@1990नाम + साल अनुमान लगाया जा सकता है
P@ssw0rdबहुत common pattern
correct-horse-battery-stapleलंबा passphrase — बेहतर
Random 4 शब्द + अंकलंबाई और randomness दोनों

मज़बूत password का सबसे बड़ा कारक लंबाई है। 12–16 अक्षर वाला random passphrase आम 8-अक्षर symbol वाले password से कहीं बेहतर है। साथ में password manager और two-factor authentication (2FA) रखें।

Defensive तरफ़ क्या करें

  • bcrypt/Argon2 + salt से password store करें।
  • Login पर rate limiting और account lockout रखें।
  • 2FA लागू करें — password leak होने पर भी सुरक्षा।
  • Leaked password सूची के खिलाफ़ जाँचें और बदलने को कहें।
  • Default password पहले login पर बदलवाएँ।
याद रखें
  • Password hash में सेव होते हैं, plain text में नहीं
  • Salt से rainbow tables बेकार होती हैं
  • लंबाई > complexity; 2FA सबसे बड़ा बचाव
  • Cracking के tools सिर्फ़ अपने lab में
Practical — 10 मिनट

अपने तीन passwords सोचें और लिखें कि उनमें कौन सी कमज़ोरी हो सकती है (नाम, साल, दोहराव)। फिर एक passphrase बनाएँ जिसमें चार random शब्द हों और उसे password manager में सेव करें।
