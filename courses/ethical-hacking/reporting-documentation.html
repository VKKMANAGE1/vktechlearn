Chapter 10 · Ethics, Law और Reporting

Report लिखना, Documentation और Career

लेसन 20 / 20·~7 मिनट·by Vïnâý Kúshwâhå

Penetration test की असली कीमत report में निकलती है। अगर finding साफ़ नहीं लिखी, तो developer उसे ठीक नहीं कर पाएगा और पूरा test बेकार चला जाएगा। अच्छी report वह है जिसे पढ़कर किसी को पूछना न पड़े — "यह कहाँ है और कैसे ठीक करें?"

Report का ढाँचा

  1. Executive summary: 1 पेज — क्या जोखिम है, कितना गंभीर, क्या पहले ठीक करें।
  2. Scope और methodology: क्या test हुआ, कब, किन tools से।
  3. Findings: severity के क्रम में, हर एक का proof और fix।
  4. Risk ratings: Critical/High/Medium/Low के साथ कारण।
  5. Remediation plan: किस क्रम में सुधार करें।
  6. Appendix: scan output, screenshots, timeline।

एक Finding का format

Title        : Public S3 bucket me documents
Severity     : Critical
Location     : https://files.example.com/reports/
Impact       : 12,000 invoices public थे
Evidence     : screenshot, HTTP 200, listing
Fix          : bucket private करें, IAM से सीमित करें
Reference    : CWE-284

यही format developer, manager और auditor — तीनों को समझ आता है। भाषा सरल रखें, blame न करें; समस्या और समाधान पर ध्यान दें।

Severity कैसे तय करें

Levelमतलब
Criticalबिना login पूरा system या data खुला
Highबड़ा data leak या admin access
Mediumसीमित access, कुछ शर्तों के साथ
Lowजानकारी लीक, अकेले नुक़सान नहीं

Severity सिर्फ़ technical नहीं — business impact भी देखें। एक low technical issue जिससे customer data खुलता है, business के लिए high हो सकता है।

Screenshots और evidence

  • हर screenshot में समय और URL दिखे।
  • Password, token और personal data blur करें।
  • Steps दोहराने लायक लिखें — developer खुद verify कर सके।
  • Original output को अलग फ़ाइल में रखें।

करियर की दिशा

Security में शुरुआत आमतौर पर SOC analyst या junior pentester से होती है। आगे web app security, network pentest, cloud security, malware analysis या red teaming में specialization होती है। मदद करती हैं — TryHackMe/HTB जैसी practice labs, OWASP Top 10 की समझ, एक मज़बूत GitHub portfolio और लिखने की आदत। Certification (जैसे eJPT, OSCP) अच्छे हैं, पर practical knowledge उनसे ज़्यादा मायने रखती है।

याद रखें
  • Report के बिना pentest अधूरा
  • हर finding: title, severity, location, impact, proof, fix
  • Severity में business impact भी देखें
  • Portfolio + practice labs करियर बनाते हैं
Practical — 10 मिनट

अपने lab के किसी एक finding को ऊपर दिए format में लिखें — title, severity, impact और fix के साथ। यही अभ्यास आपकी पहली professional report का नमूना बनेगा।
